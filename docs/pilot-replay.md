# Checkpoint 3: physical replay of the human pilot

This report preserves the historical full-reference experiment. Use `--termination reference` for its replay commands; see [current goal-or-timeout behavior](stopping.md).
The Panda physically pushes a passive simulated die using the finger trajectory extracted from the user's recording. The object's pose is set once at reset; during rollout it changes through MuJoCo contact dynamics. This is hand-coded retargeting, not policy training.

## Run

```bash
cd humanoid-push
uv sync --locked --python 3.12
# Requires the original pilot and tracks. Recreate tracks if needed:
uv run --locked push-track
uv run --locked push-replay
```

If you already have the pilot tracks, only the last command is necessary. Outputs at `outputs/pilot_replay/`: `replay.mp4`, `preview.png`, `metrics.json`, `rollout.npz`. The video has a Panda overview on the left and physical contact close-up on the right. The blue disc indicates the demonstrated endpoint.

For a fast physics-only run:

```bash
uv run --locked push-replay --no-video --output outputs/pilot_replay_physics
```

## How the recording drives the robot

1. Select the valid finger-marker tracks from **3.6–8.7 seconds** of the pilot. This pilot-specific segment was selected after inspecting the video/tracks; it is not an automatic general contact detector.
2. Subtract half the calibrated rectangle dimensions to place the paper origin at the centre of the simulation table. Keep distances at their measured scale.
3. Add a **constant marker-to-tool XY offset**, approximately **[16.7, 4.1] mm**, estimated from the median object-minus-marker separation during contact, minus the object's support radius and tool thickness. This uses the human object track for a single calibration, not as a time-varying robot reference. It includes geometric approximations and parallax.
4. Linearly resample the tracked finger trajectory to **20 Hz**. All contact-segment detections must be valid; missing contact frames are rejected rather than filled silently. Reference increments preserve the recorded finger motion.
5. Set a fixed downward grip-site orientation and **0.868 m grip-site height** above a table at **0.800 m**. A rigid stem and an **8 × 24 × 12 mm flat paddle** extend from the grip site; the paddle centre is 60 mm below it. Its nominal bottom is 2 mm above the table. A visible shaft and collar connect it to the gripper. The mount is rigidly fixed to the grip body, not held by a simulated friction grasp. Its sleeve/collar are massless visual geometry; the lower stem and paddle provide physical contact. This is a simulated attachment, not a claim about physical Panda hardware.
6. Script the approach, lowering, settling and withdrawal. During the push, desired XY comes from the human reference. Position feedback uses `(desired XYZ − simulated grip XYZ) / 0.05`, clipped to ±0.2. Rotation feedback uses the actual **grip-site** rotation error divided by 0.5, clipped to ±0.3. The stock operational-space controller supplies joint torques.

The legacy `robot0_eef_quat` observation refers to an upstream body frame with a fixed rotation relative to the grip site; using it as the grip-site orientation caused premature paddle contact. The replay now reads `site_xmat` for orientation.

The cube is **17 mm on each side**, following the user's approximate measurement. Density is an assumed 2000 kg/m³ (mass about 9.8 g). Table/object sliding friction is an assumed 0.3. These are not recovered from the video. The cube and paddle use simple collision geometry rather than an exact real die/fingertip model.

## Observations and action-label provenance

No live object-position feedback modifies the replay motion. Simulated end-effector position and grip-site orientation supply low-level feedback. Cube pose is used for initialisation and diagnostics. The recorded object track supplies initial placement, the constant calibration offset and demonstrated endpoint.

`rollout.npz` saves:

- `observations_before` / `observations`: pre-/post-action `[eef_x, eef_y, eef_z, object_x, object_y, object_z]` in world metres.
- `eef_quat_site_before` / `eef_quat_site_after`: world grip-site orientation, XYZW quaternions.
- `actions`: derived, normalised OSC delta XYZ, delta rotation and gripper command; one action for each pre-action observation.
- `action_time_s` / `observation_time_s`, `target_xyz`, `phases` and tool-object contact flags.
- `human_reference_xy` / `human_time_s`: calibrated and offset contact reference.

These robot actions are generated by retargeting and simulator feedback. They are **not directly collected robot demonstrations**.

## Pilot outcome

| Diagnostic | Corrected flat-paddle replay |
|---|---:|
| Physical die displacement | 7.95 cm |
| Observed human die displacement | 8.16 cm |
| Final distance from demonstrated endpoint | 4.63 mm |
| Motion before recorded push starts | 0 mm |
| Push reference tracking RMS error | 3.15 mm |
| Tool-object contact control steps | 101 |
| Tool-table contact control steps | 0 |
| Object stayed on table | Yes |
| Video frames decoded | 373 / 373 |

The pilot gate checks finite simulation state, >4 cm physical displacement, <2 cm endpoint distance, <5 mm lift, retention on the table, <2 mm pre-push movement, physical contact and complete video decoding. The 2 cm gate is a setup diagnostic and should not automatically become the final evaluation tolerance for a 17 mm die.

This is **one tuned pilot**, not held-out performance. Its endpoint comes from the observed final die position, not an independent target. Subsequent trials must specify targets and evaluate new starts.

## What failed and changed

- Initial narrow rounded contact: die moved 5.97 cm but missed the endpoint by 2.59 cm.
- Initial flat paddle: endpoint error improved to 6.89 mm, but 7.38 mm of die movement occurred during lowering. That result was rejected as contaminated by the scripted approach.
- Correcting body-versus-grip-site orientation removed early motion and produced the final result above. The human reference trajectory was unchanged.

Saved metrics for these development runs are included under `docs/examples/pilot_replay/`. They document development observations; the first two runs predate the grip-site orientation fix and are not claimed as a controlled tool comparison.

## Next

Keep the same fixed camera, marks, die and marker colours. Collect a small batch first, then expand to approximately 10–20 usable pushes. Vary starting XY and direction while keeping objects and markers visible and avoiding lifting/tipping. Mostly forward pushes and modest diagonal variation are the easiest next step for this fixed paddle orientation; wider direction coverage will require explicit tool-orientation retargeting.

Record each clip's intended endpoint independently (a small dark target mark outside the die footprint, with a clearly defined reference point). Preserve original videos and use per-clip calibration files when camera framing changes. Keep tuning starts separate from the later held-out simulation comparison.
